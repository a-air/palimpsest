# 和「山韵记忆」的对照

> 这份对照来自一次真实的同业评审（对方是自己搭的一套记忆系统，非公开项目）。
> 保留在这里，是因为它比自吹的 README 更能说明这个项目该往哪走。

| 维度 | palimpsest | 山韵记忆 |
|---|---|---|
| 形态 | 离线 CLI（批处理） | 在线服务 + Agent 工具 + 面板 |
| 存储 | JSONL + archive 目录，SQLite 只做检索索引 | SQLite 单一真相 |
| 写入口 | 无（每次手动跑命令） | 策略引擎唯一写者，自动留痕 |
| 时间 | `valid_from` / `valid_to` + 版本链 | 双时态：现实有效期 + 系统写入时间，支持时间切片查询 |
| **压缩质量** | **探针问答 + F1 评分** | 无（只保证可追溯，不保证压缩没丢） |
| 生命周期 | 热 → 封存 → 冷箱（4 份一审，≥85 才入冷箱） | demoted / archived / superseded |
| 宪章层 | 独立一层，永不压缩 | 靠 `fact_type` 打标，仍混在 `fact_state` 里 |
| 可视化 | 无 | 六视图监控页 |
| 联网 | 要模型 API（智谱 / DeepSeek） | 本地优先，不联网 |

## 对方给的结论

> 它的"灵魂"（不可变原文 + 版本链 + 不删除）我们已经有了，而且做得更完整（双时态、时间切片、在线策略）。
> 它真正领先的是"验收"这一环——我们保证"存得住、查得到、说得清来源"，但不保证"压缩/技能没丢关键信息"。
> 这正是我们最薄的一环，尤其是 skills：现在 `success_rate` 只统计"用过之后成没成功"，
> 完全没人管"压缩时有没有把关键步骤压丢"。

## 读完之后的判断

**不要跟它比存储。** 双时态、单一真相、可视化面板，这些是"记忆系统"该有的，但这个项目没有、也不该去补——
补成了也只是又一个记忆库。

**该做的是那把尺子。** 任何记忆系统（包括山韵）都可以把自己的 `raw + node` 丢进来：

```bash
python refiner.py score --raw raw.md --node node.json          # 脚本分
python refiner.py probe --raw raw.md --node node.json -k 6     # 探针验收
python refiner.py judge --raw raw.md --node node.json          # 外部裁判找漏
```

输出是可以横向比较的数字，而不是"我觉得我压得挺好"。

**下一步方向**（如果继续做）：

- 把 `score` / `probe` 抽成一个可被别人 import 的库接口，不再依赖目录结构
- 探针题库按领域分开（对话记忆 / 操作步骤 / 事实更新），这样"技能压缩有没有丢步骤"也能量
- 输出一份标准格式的验收报告（JSON），任何系统都能接

> 一句话：**别人负责记住，这个项目负责证明它没记丢。**
